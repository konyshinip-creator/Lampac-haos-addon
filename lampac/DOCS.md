# Lampac — add-on для Home Assistant OS

Backend-сервер [Lampac Next Generation](https://github.com/lampac-nextgen/lampac)
(апстрим; репозиторий `immisterio/Lampac` — популярный форк с тем же кодом)
для клиента Lampa.

Собран поверх официального образа **`ghcr.io/lampac-nextgen/lampac`**
(GitHub Container Registry, multi-arch: amd64/arm64).

> ⚠️ Раньше в этом аддоне ошибочно использовался `docker.io/immisterio/lampac` —
> такого места распространения образа не существует, отсюда были ошибки
> `pull access denied`. Правильный и единственный официальный образ — GHCR,
> как указано в README проекта и в его `docker-compose.yaml`/Helm-чарте.

## Что включено и почему

По умолчанию в самом Lampac (файл `config/base.conf` в апстриме) в
`SkipModules` (то есть выключены) находятся: `Catalog`, `DLNA`, `Tracks`,
`Transcoding`, `WebLog`, `CacheMedia`, `ProxyLimiter`, `ForkPlayerXML`,
`MsxNative`, `TelegramAuth`, `TelegramAuthBot`. WAF и accsdb тоже выключены.

**`TorrServer`, `JacRed`, `Sync` и `TimeCode` в этот список не входят —
они включены уже "из коробки"**, без какой-либо дополнительной настройки.
Опции `enable_torrserver` / `enable_jacred` / `enable_sync` / `enable_timecode`
в этом аддоне нужны только если вы **захотите их выключить** — тогда имя
модуля добавляется в `BaseModule.SkipModules` в `init.conf`.

Аниме-провайдеры — это не модули, а источники контента внутри модуля
`Online` (папка `Modules/OnlineAnime` в апстриме). Каждый включается
собственным ключом верхнего уровня в `init.conf`:

```json
{ "AniLibria": { "enable": true } }
```

Опция `anime_providers` (список через запятую) в аддоне включает именно так
перечисленные провайдеры. По умолчанию:

`AniLiberty, AniLibria, Animevost, AnimeON, AniMedia, MoonAnime, Mikai, AnimeLib`

(в апстриме всего 12 аниме-источников: к этому списку ещё относятся `AnimeGo`,
`Animebesst`, `Dreamerscast` и универсальный `Kodik` — они не трогаются
этим аддоном и остаются в том состоянии, в котором идут по умолчанию).

Аддон **не выключает** ничего, что не просили явно выключить — он только
добавляет `enable: true` для перечисленных провайдеров и не трогает
остальную конфигурацию.

## Где лежат конфиги (persistent)

Файлы монтируются в постоянную папку конфигурации аддона на хосте (в
зависимости от версии Supervisor видна как `/addon_configs/local_lampac/`
или `/app_configs/local_lampac/` — смотрите через Samba share или Studio
Code Server):

- `init.conf` — основной конфиг Lampac (JSON, поддерживает горячую
  перезагрузку — правки применяются без перезапуска контейнера)
- `passwd` — пароль root (нужен для `/weblog` и части служебных функций)

Эти файлы создаются один раз при первом запуске (копируются из образа,
если там есть дефолтные, иначе с нуля) и дальше только патчатся аддоном
по вашим опциям при каждом старте — ручные правки не теряются.

Если пароль не задан ни опцией, ни образом, аддон сгенерирует случайный
и один раз выведет его в лог аддона при первом запуске — проверьте
Log-вкладку после первого старта.

## Проверка после первого запуска

Формат `init.conf` может отличаться между версиями Lampac. После первого
старта стоит:

1. Открыть `http://<IP HAOS>:9118/version` — убедиться, что сервер вообще
   поднялся и вернул версию.
2. Проверить `http://<IP HAOS>:9118/online.js` (плагин Lampa) — если
   аниме-провайдеры включились, они должны быть видны в списке источников
   при поиске тайтла в самой Lampa.
3. Если что-то не так — либо передайте недостающие ключи через опцию
   `extra_init_json` (глубоко подмешивается в `init.conf` при каждом
   старте, ваши ключи имеют приоритет), либо отредактируйте `init.conf`
   напрямую в постоянной папке конфигурации.

## Сеть

Порт `9118` проброшен как обычный порт Docker (не через Ingress), потому
что клиенты Lampa (Android TV / браузер / MX Player и т.д.) должны
обращаться к серверу напрямую по IP хоста.

## Опции

| Опция | По умолчанию | Описание |
|---|---|---|
| `root_password` | *(пусто → авто-генерация)* | Пароль для `/weblog` и служебных функций |
| `port` | `9118` | Порт Lampac |
| `timezone` | `Europe/Kiev` | Часовой пояс контейнера |
| `enable_torrserver` | `true` | Модуль TorrServer (уже включён в апстриме; `false` — добавить в SkipModules) |
| `enable_jacred` | `true` | Модуль JacRed |
| `enable_sync` | `true` | Модуль Sync |
| `enable_timecode` | `true` | Модуль TimeCode |
| `anime_providers` | см. выше | Список аниме-источников через запятую, которые нужно явно включить |
| `extra_init_json` | *(пусто)* | Произвольный JSON, подмешиваемый в `init.conf` при каждом запуске |

## Автообновление

Этот аддон собирается из тега `ghcr.io/lampac-nextgen/lampac:latest`, а не
из зафиксированной версии — то есть каждый **Rebuild** уже подтягивает
самую свежую сборку Lampac. Вопрос только в том, как эти Rebuild-ы
запускать:

- **Локальный аддон (папка в `/addons/`)** — только вручную: Settings →
  Add-ons → Lampac → Rebuild. У HA нет способа сам понять, что для
  локального аддона "есть обновление", и он не покажет никакого бейджа.
- **Git-репозиторий + включённый Auto update** — полностью автоматически.
  В репозитории лежит `.github/workflows/check-lampac-update.yml`,
  который ежедневно проверяет образ на GHCR и, если он изменился, бампает
  `version:` в `config.yaml`. Supervisor видит новую версию при обычной
  проверке репозиториев и с включённым переключателем **Auto update**
  сам пересобирает и перезапускает аддон. Подробности — в `README.md`
  корня репозитория ("Установка — вариант B").

## Обновление образа

Аддон использует тег `ghcr.io/lampac-nextgen/lampac:latest` — пересоберите
аддон (Settings → Add-ons → Lampac → Rebuild), чтобы подтянуть свежую
версию: `docker build --pull` заново стянет актуальный слой.

## Технические детали сборки

Базовый образ Lampac по умолчанию работает от непривилегированного
пользователя (в нём даже `apt-get` падает с Permission denied). Поэтому
Dockerfile явно переключается на `USER root` в начале — это нужно и для
установки `jq` через `apt-get`, и для рантайма: `run.sh` при каждом старте
контейнера должен иметь право писать/симлинковать файлы внутри `/lampac`.

`jq` ставится именно через `apt-get` (glibc-сборка), а не копированием
готового бинарника из другого базового образа (например Alpine) — Alpine
использует musl libc, и такой бинарник физически не запускается в
Debian/Ubuntu-окружении (`cannot execute: required file not found`,
поскольку в системе нет пути `/lib/ld-musl-x86_64.so.1`, на который
рассчитан musl-линкованный файл). Это частая ловушка в multi-stage
Dockerfile — переносить бинарники между образами с разным libc можно
только если они статически слинкованы или архитектурно/ABI совместимы.

## Если Lampac падает с ошибкой ld.so при старте

Если в логах аддона видно что-то вроде:

```
Inconsistency detected by ld.so: ../sysdeps/x86_64/dl-machine.h: ...
elf_machine_rela_relative: Assertion ... failed!
```

— это ошибка динамического линковщика glibc про повреждённые ELF-релокации
в самом бинарнике `dotnet`/`Core.dll`. Она не связана с логикой этого
аддона и почти всегда означает, что слой образа лёг на диск повреждённым
(нередко встречается на платах с eMMC-накопителями при большой нагрузке
на запись). Что помогает:

1. Полностью удалить локально собранный образ и пересобрать с нуля:
   Settings → Add-ons → Lampac → Uninstall, затем заново Install
   (это форсирует чистую пересборку, а не переиспользование потенциально
   повреждённого слоя из кэша).
2. Проверить свободное место на диске: Settings → System → Storage —
   если места мало, Docker иногда обрывает запись слоя на середине.
3. Проверить журнал ядра на ошибки накопителя: через SSH-аддон —
   `dmesg | grep -iE 'mmc|i/o error'`.
4. Как диагностика "это не в аддоне ли дело" — через SSH-аддон вручную
   стянуть и запустить тот же образ в обход Supervisor:
   `docker run --rm --platform linux/amd64 ghcr.io/lampac-nextgen/lampac:latest dotnet Core.dll`
   Если падает так же — проблема точно на уровне хоста/образа, а не в
   нашем `Dockerfile`/`run.sh`.
